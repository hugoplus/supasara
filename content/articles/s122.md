## 1. 核心术语

| 英文 | 全称（如适用） | 中文 |
|---|---|---|
| EDI | Electronic Data Interchange | 电子数据交换 |
| API | Application Programming Interface | 应用程序接口 |

EDI standardizes business document exchange, while APIs expose application data or functions through defined interfaces.

EDI强调结构化业务文件交换；API定义应用如何提供数据或功能接口，两者可共同使用。

## 2. 概念与使用场景

比较时要区分业务语义、数据格式和传输机制。企业可以通过API传送EDI格式文件，也可使用API查询订单状态。EDI不必然只能批量处理，API也不保证实时且无故障。选择取决于伙伴要求、交易量、响应时间和现有系统能力。

| 对比维度 | EDI | API |
|---|---|---|
| 主要侧重 | 标准业务文件交换 | 提供应用数据或功能接口 |
| 语义要求 | 标准加伙伴实施规则 | 接口契约加业务约定 |
| 共存方式 | 可作为传输的数据内容 | 可作为交换入口 |

## 3. 一个工作案例

**教学示例**

零售商通过EDI发采购订单，供应商通过API实时查询承运状态。两种机制服务不同需求，集成层把它们关联到同一订单，并统一处理鉴权、重试和异常，而不是为了“更新技术”强行替换所有接口。

## 4. 工作中怎么说

| 场景 | 英文表达 | 中文意思 |
|---|---|---|
| 选择 | Does the partner require an EDI document or an API call? | 合作方要求EDI文件还是API调用？ |
| 时效 | What response time does this process need? | 这个流程需要什么响应时间？ |
| 共存 | The API can carry an EDI payload. | API可以传送EDI格式的数据内容。 |

## 5. 常见混淆与使用边界

- 不能简单说EDI过时、API一定便宜，成本取决于生态和实施条件。
- 接口连通不等于双方理解相同字段，业务语义仍需映射和确认。

## 6. 要点回顾

- 不要把标准、格式与传输方式混成一层。
- 按业务需求设计可共存的接口。
- Different interfaces can support one process. 不同接口可服务同一流程。
